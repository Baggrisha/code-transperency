# Фронтенд uzniki’s project

Интерфейс «Контроля исполнения» использует предоставленную айдентику: светлые поверхности, тёмно-синий `#26306E`, оранжевый `#FF7700`, Unbounded в заголовках и Montserrat в основном тексте. Серверный интерфейс и автономный прототип реализованы на React; Vite собирает их в `web/dist` для FastAPI. Исходная разметка, компоненты и стили разделены между HTML, `web/src` и `web/assets`.

## Приложенный HTML-прототип

`web/prototype.html` — адаптация присланного пользователем HTML. В нём сохранены исходные сценарии: реестр, шесть вкладок дела, отдельная карточка сигнала, комментарии, завершение рассмотрения, архив и TXT-экспорт вопросов. Кнопки выбора типа и просмотра открывают окна в общем оформлении. Раскрытый список типов повторяет предоставленный макет.

Исходная модель хранения сохранена: ключ `control-execution-demo-v1` в `localStorage`, файлы — только в памяти вкладки. Существующие данные в этом ключе не переводятся в другую схему. Если браузер запрещает сохранение, интерфейс продолжает работать в памяти и показывает сообщение. Для встроенных документов доступен предпросмотр реквизитов, загрузка настоящего файла позволяет открыть оригинал. Автоматическое распознавание и сверка в автономном HTML по-прежнему не выполняются; эти возможности доступны в серверной версии.

Встроенный комплект сохраняет данные присланного HTML: четыре документа с исходными именами, размерами и версиями, один сигнал с пояснением и источниками, предпросмотры всех четырёх документов. Из видимого интерфейса удалены подписи про прототип и локальный режим, демонстрационные ярлыки, ID DEMO-001 в надзаголовке и общие нижние дисклеймеры. Подзаголовок рабочей области содержит только «Контракт номер — статус». Описание встроенной проверки: «Поставка уличных скамеек по контракту ГК-2026/0142.» Внутренние признаки, идентификаторы и числовые данные сохранены. Исходная fixture `tests/fixtures/prototype_source.json` остаётся контрольным источником данных; проверки отдельно учитывают согласованные изменения текстов. Начальные истории и комментарии остаются пустыми.

Кнопка «Открыть проверку» находится рядом с созданием проверки. Она открывает существующий неизменённый комплект или добавляет свежую копию с отдельным ID, если прежний комплект был отредактирован. Изменённое дело, пользовательские проверки, решения и доступные в памяти файлы сохраняются. При загрузке заменяются только прежние заводские описания встроенного комплекта; пользовательские описания и намеренно очищенные поля не заполняются автоматически.

Создать самостоятельный файл со встроенными шрифтами и стилями:

```bash
python scripts/export_prototype.py --output /tmp/uzniki-prototype.html
```

Он открывается в браузере без сервера. В работающем приложении тот же вариант доступен по `/prototype`. Для интеграции с API предназначен основной интерфейс по `/`. Базовые стили находятся в `styles.css`, дополнения для прототипа — в `prototype.css`, иконки — в `icons.css`. Общая фирменная тема `brand.css` подключается последней.

## Запуск

Используйте существующее окружение проекта и инструкции установки в корневом README. Из корня репозитория:
Сначала установите зависимости и соберите интерфейс: `npm ci && npm run build`.


```bash
python -m uvicorn kontrol.api:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000/`. Если задан `KONTROL_API_TOKEN`, введите токен кнопкой «Доступ» в боковом меню. Токен сохраняется только в `sessionStorage` текущей вкладки. Новый фронтенд использует относительные пути `/api/...` и локальные `/assets/...` того же сервера.

Сервер отдаёт собранный `web/dist/index.html`. Для просмотра без сервера используйте отдельный автономный экспорт, описанный ниже.

## Экраны и маршруты

| Экран | Маршрут | Что доступно |
| --- | --- | --- |
| Все проверки | `#checks` | Счётчики, поиск по номеру и названию, фильтр состояния, создание дела, демонстрационные комплекты. |
| Обзор | `#case/{id}/overview` | Документы и сигналы, реквизиты карточки, переход к загрузке. |
| Документы | `#case/{id}/documents` | Выбор файлов и drag-and-drop, загрузка, изменение категории, оригинал/сохранённые реквизиты, исключение из сверки. |
| Распознавание | `#case/{id}/recognition` | Список источников, просмотр, полный редактор извлечённых реквизитов и товарных строк. |
| Сопоставление | `#case/{id}/matching` | Контракт / накладная / приёмка / состояние, дата среза, запуск сверки, неоднозначные и ручные связи. |
| Результаты | `#case/{id}/results` | Сигналы и их источники, решение и комментарий, количества, экспорт PDF/HTML/CSV/JSON. |
| История действий | `#case/{id}/actions` | События текущего дела и их подробности. |
| История проверок | `#history` | Сохранённые запуски, страницы журнала, открытие результата конкретного запуска. |

Для конкретного сохранённого запуска используется маршрут `#case/{id}/{tab}/run/{run_id}`, например `#case/demo-001/results/run/demo-run-001` в автономном макете. Выбранный запуск сохраняется при переходе между вкладками; повторное открытие ссылки показывает именно его результат. Маршрут без `/run/{run_id}` открывает последний запуск дела.

К основным экранам добавлены диалоги создания дела, выбора типа, просмотра исходника, отмены/восстановления документа и настройки доступа. Редактор реквизитов сохранён со всеми проверками и явными отметками подтверждения полей.
Диалог закрывается при нажатии вне окна или клавиши Escape; несохранённые изменения при закрытии не сохраняются.

Размытые цветные пятна и полупрозрачные поверхности продолжают графические элементы предоставленной айдентики. Текст остаётся на читаемом спокойном фоне.

На широком экране сохранены sidebar шириной 274 px и начало основной зоны на x=320. Типографика уменьшена относительно первоначальной версии:

| Элемент | Размер |
| --- | --- |
| Основной текст и значения полей | 16 px |
| Ячейки таблиц | 15 px; заголовки колонок 11 px |
| Предупреждения | 14 px; на экранах до 500 px — 13 px |

| Подписи полей и пояснения | 13 px |

Пояснения, предупреждения, подписи форм и текст источников выровнены по левому краю; группы действий располагаются от левого края своего блока. Заголовки и ячейки таблиц, статусные бейджи, подписи и числа счётчиков центрированы. Блоки сравниваемых значений также выровнены по центру. Небольшие активные подписи используют тёмно-синий или текстовый акцент `#3F4A99`. Основные кнопки имеют белую надпись на тёмно-оранжевом фоне; яркий фирменный оранжевый сохраняется в декоративных акцентах. Состав экранов и последовательность действий сохраняются при смене оформления.

Шрифты находятся в `web/assets/fonts`, включая кириллицу и лицензии. Браузеру не нужен CDN. Используются переменные файлы Unbounded с диапазоном веса 200–900 и Montserrat с диапазоном 100–900. Оба автономных экспорта встраивают шрифты в HTML вместе с текстами лицензий. Источники и контрольные суммы приведены в `web/assets/fonts/README.md`.

Адаптивная вёрстка сохраняет общий стиль. На узких экранах боковая навигация переходит наверх, панели располагаются вертикально, таблицы прокручиваются внутри своего контейнера. Не используется масштабирование всей страницы или фиксированное обрезание по высоте 1080 px.

### Таблицы и счётчики

Все таблицы используют общий класс `data-table` и класс своего назначения: `registry-table`, `matching-table`, `signals-table`, `history-table`, `quantity-table` или `document-items-table`. Заголовки `th` и данные `td` центрированы по горизонтали и выровнены по середине строки. Содержимое бейджей и плашек статуса центрировано внутри них; подписи статуса могут переноситься по словам.

Таблицы занимают доступную ширину (`width: 100%`), используют `table-layout: auto` и `min-width: 0`. Прежние фиксированные доли колонок 18/25/26% и минимальная ширина таблиц 900 px убраны. Компактные колонки `cell-id`, `cell-count`, `cell-date`, `cell-unit`, `cell-amount`, `cell-action` имеют `width: 1%` и `white-space: nowrap`: 1% служит подсказкой сжать колонку, а её фактическую ширину определяет содержимое. Колонки описания и статуса допускают перенос текста; длинное слово в обычной ячейке может переноситься без принудительного разбиения всех слов на буквы. Текст кнопки действия и отдельная стрелка сохраняются в одной строке.

Если минимальная ширина содержимого всё же превышает доступную область, горизонтальная прокрутка остаётся внутри `.scroll`. Пустое состояние занимает полную строку через `colspan`; ячейка `.table-empty` и вложенный `.empty-message` центрируют сообщение размером 13 px.

Только в пустом реестре применяется `table-layout: fixed` с долями колонок 18/26/12/16/14/14%. Центр третьей колонки находится ровно на 50% ширины таблицы: заголовок «Статус» и пустое сообщение стоят на одной оси. Селектор `:has()` реагирует и на результаты фильтрации без дополнительного JavaScript. Минимальная ширина пустой таблицы на экране — 768 px, чтобы заголовки не пересекались; на узком экране прокрутка остаётся внутри карточки. Печатная версия этого минимума не получает. После появления данных возвращается автоматическая ширина колонок.

В карточках счётчиков центрированы и подписи, и числа. Для подписи предусмотрено минимум две строки: `min-height: 2.8em` при `line-height: 1.4`. Это сохраняет место под перенос текста; более длинная подпись может увеличить высоту. Числа используют табличные цифры (`tabular-nums`).

При печати `.scroll` снимает ограничение прокрутки, таблицы сохраняют `min-width: 0`; фиксированная раскладка остаётся только у пустого реестра для общей центральной оси. Ячейки, кнопки и бейджи получают текст 10 px, заголовки колонок — 8 px. Для всех колонок разрешены переносы, включая длинные идентификаторы; заголовок таблицы оформлен как повторяемая группа, внутри строки задано предотвращение разрыва. Эти правила описывают CSS печати, а не результат браузерной проверки.

### Контраст текста и состояний

Белая надпись на ярком `#FF7700` слабо отделяется от фона, особенно при небольшом размере текста. Поэтому фон основных кнопок затемнён, а фирменный `#FF7700` оставлен для декора. Для белого текста `#FFFFFF` расчёт контраста даёт следующие значения:

| Состояние основной кнопки | Фон | Контраст с белым текстом |
| --- | --- | --- |
| Обычное | `#B85000` | 5.02:1 |
| Наведение | `#A94A00` | 5.73:1 |
| Нажатие | `#934300` | 6.90:1 |

Вторичный текст использует непрозрачный `#485066`, текстовый акцент — `#3F4A99`. Предупреждения показывают текст `#303746` на фоне `#FFF3E8`; подписи предупреждающих бейджей используют `#713300`. У отключённых кнопок и пунктов списка сохранена полная непрозрачность (`opacity: 1`): текст `#535B70`, светло-серый фон `#E5E8EF`. Прежнее общее затухание до `opacity: .45` не применяется. Выбранный тип документа выделен светло-лавандовым `#EEF0FA` с тёмно-синим текстом.

Значения контраста относятся к указанным сплошным парам CSS-цветов. Они не подтверждают доступность всего интерфейса и не заменяют проверку отображения в браузере.

### Исходные иконки

Все 20 иконок берутся из предоставленного листа `web/assets/icons/reference-sheet.png` размером 1280×720 px. Пиксели листа не изменяются. `web/assets/icons/manifest.json` содержит контрольную сумму исходника, названия и координаты окон 112×112 px; `web/assets/icons.css` показывает эти окна через один CSS-спрайт. Класс `.identity-icon` задаёт общий источник, а классы вида `.identity-icon--folder` выбирают нужную иконку. Стеклянные детали, синий фон и свечения принадлежат исходному изображению.

В интерфейсе используются эти оригинальные изображения. PNG не содержит прозрачного канала; его синий фон сохраняется. Размер окна в интерфейсе задаётся CSS независимо от координат в manifest: обычно 48 px в навигации, 40 px у заголовков разделов и 72 px в загрузке.

Экспорт отдельных иконок:

```bash
python scripts/export_icons.py --output-dir /tmp/uzniki-icons --zip /tmp/uzniki-icons.zip --catalog /tmp/uzniki-icons.html
```

Команда создаёт 20 самостоятельных SVG-файлов. Каждый SVG содержит исходный PNG внутри файла и показывает соответствующее окно через `viewBox`; соседний PNG для его открытия не требуется. **Это SVG-контейнеры с растровым содержимым и сохранённым фоном**, а не прозрачные векторные контуры. В архив также входят исходный PNG, manifest, пояснение к формату и HTML-каталог для просмотра и скачивания отдельных файлов. Параметр `--catalog` создаёт отдельный самостоятельный HTML-каталог.

## Поведение и данные

### Реальный интерфейс

Данные приходят от API. В рабочей версии сообщения о хранении файлов и распознавании отражают возможности сервера: он сохраняет документы и выполняет извлечение/сверку. Доступность OCR зависит от установленного Tesseract/Poppler, как и до изменения оформления. В адаптированном исходном прототипе сохранены его прежние ограничения.

Сопоставление показывает значения сохранённого запуска. Количество и денежные значения выводятся как строки, без повторного расчёта в JavaScript. Отсутствующие или неоднозначные данные остаются отмеченными. Разные единицы измерения не объявляются эквивалентными на уровне интерфейса.

### Реквизиты карточки

Кнопка «Сохранить реквизиты» сохраняет название, описание и номер в карточке дела через `PUT /api/cases/{id}`. Это информационные поля карточки: они не переписывают распознанные значения исходников и не подтверждают их. Документ редактируется отдельно на вкладке «Распознавание».

Метаданные защищены отдельным `expected_metadata_revision`. Ошибка 409 оставляет форму доступной для исправления. Изменение подписи карточки не делает старую сверку неактуальной; изменение документа делает.

### Категории и редакции

Сервер поддерживает категории «Контракт», «Спецификация», «Накладная», «Документ о приёмке», «Дополнительное соглашение». После изменения категории её нужно подтвердить по оригиналу в полном редакторе; одно изменение типа не подтверждает документ автоматически.

«Исправленная версия» открывает полный редактор: исправление сохраняет исходную категорию, а связь версий задаётся полями заменяемого документа и редакции. «Другое» присутствует в макете, но недоступно для реальной сверки, поскольку в модели API такой категории нет. Интерфейс объясняет, что сначала нужно уточнить роль документа.

Кнопка «×» означает **исключение из следующей сверки**, а не физическое удаление исходника. Диалог показывает это явно, требует проверяющего и причину; документ получает статус «Отменён». Его можно восстановить. Файл и история сохраняются.

### Просмотр и решения

При наличии исходника «Открыть» показывает PDF, изображение или текст. Для форматов без встроенного просмотра есть скачивание. Если оригинала нет, например в синтетическом комплекте, интерфейс прямо сообщает об этом и показывает сохранённые реквизиты. Источник старого запуска берётся из снимка этого запуска.

Счётчик рассмотренных сигналов учитывает последнее решение по каждому сигналу. Несколько комментариев к одному сигналу не увеличивают счётчик. Решения предыдущих запусков не смешиваются с текущими.

## Автономная передача макетов

```bash
python scripts/export_frontend.py --output /tmp/uzniki-frontend.html
```

Команда создаёт один HTML со встроенными стилями, шрифтами, исходным листом иконок и синтетическим комплектом: «Поставка уличных скамеек», ГК-2026/0142, четыре документа, 10 / 8 / 10 шт. и один сигнал. По умолчанию файл открывает «Сопоставление». Для другого начального экрана используйте фрагмент, например `#checks` для реестра или `#case/demo-001/documents` для документов. Рабочая версия на сервере по умолчанию открывает реестр.

В автономном файле работают переходы, поиск, фильтры, модальные окна, изменение реквизитов и решений. Данные хранятся только в памяти открытой вкладки. Реальные файлы не распознаются, новая сверка не выполняется. Экспорт JSON содержит встроенные данные; PDF, HTML и CSV формирует рабочий сервер. Вместо общих служебных плашек интерфейс показывает короткое сообщение при попытке выполнить недоступную операцию.

Автономный файл не читает токен из `sessionStorage`; кнопка «Доступ» в нём убрана, поскольку подключения к серверу нет. Перезагрузка файла возвращает исходный синтетический комплект.

Генератор читает только синтетический fixture T02 из репозитория. Каталог `data`, пользовательские документы и токены в экспорт не попадают. Для визуального примера добавлена спецификация и изменены подписи документов; количество 10 / 8 / 10 и единственный сигнал проверяются настоящим движком перед созданием файла.

## Проверки

```bash
node --test tests/test_web_editor.js tests/test_sku_links.js tests/test_frontend_navigation.js
node --test tests/test_frontend_prototype.js
node scripts/check_web.js
python -m unittest tests.test_case_metadata tests.test_api tests.test_backend_integration tests.test_review_storage -q
python scripts/export_frontend.py --output /tmp/uzniki-frontend.html
python scripts/export_prototype.py --output /tmp/uzniki-prototype.html
python scripts/export_icons.py --output-dir /tmp/uzniki-icons --zip /tmp/uzniki-icons.zip --catalog /tmp/uzniki-icons.html
```

Node-проверки выполняют реальный inline-script приложения в минимальном DOM и покрывают редактор, подтверждения значений, ручные связи и навигацию. Для прототипа дополнительно проверяются полное соответствие исходным данным, заполненные значения форм и восстановление демо с сохранением пользовательских дел. Это не браузерные тесты и не подтверждение визуального отображения. Перед слиянием полезно открыть HTML на 1920, 1440 и 390 px и пройти реестр → документы → тип/просмотр → распознавание → сопоставление → результаты → историю.

При изменении оформления отдельно проверьте подключение `icons.css` перед `brand.css`, а `brand.css` — последним в обоих HTML. В самостоятельных экспортированных файлах не должно оставаться ссылок на локальные CSS, файлы шрифтов и лист иконок: тема, `@font-face` и PNG должны быть встроены. Для иконок сравните SHA-256 исходного PNG с manifest и проверьте наличие всех 20 окон. Эти статические проверки подтверждают упаковку ресурсов; визуальную проверку они не заменяют.
