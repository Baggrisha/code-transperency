# Извлечение документов

Входной модуль работает локально. Тексты и изображения не отправляются во внешние сервисы. Это проверяемый парсер реквизитов и таблиц: произвольная вёрстка договора не гарантирует автоматическое распознавание всех условий.

## Поддерживаемые файлы

| Формат | Обработка | Источник поля |
| --- | --- | --- |
| JSON | Проверка объекта `Document` по модели Pydantic | Имя файла, индекс строки и путь поля |
| TXT, CSV, TSV | Реквизиты с подписями и таблица с заголовками | Имя файла и физический номер строки |
| DOCX | Абзацы с реквизитами и настоящие таблицы Word | Имя файла и строка таблицы; номер страницы не выдумывается |
| PDF с текстом | Текст и таблицы через pdfplumber | Имя файла, страница и строка таблицы |
| PNG, JPEG, одностраничный TIFF | Локальный Tesseract | Имя файла, страница и распознанная строка |
| PDF из сканов и смешанный PDF | Poppler преобразует страницы с изображениями в PNG, затем Tesseract; результаты требуют проверки | Исходная страница PDF и распознанная строка |

По умолчанию OCR использует `rus+eng`. Если нужный языковой пакет отсутствует, возвращаются `OCR_LANGUAGE_MISSING` и неполный документ. Английская модель не подставляется вместо русской. Если Tesseract вернул не TSV, возвращается `OCR_FAILED`, даже при успешном коде завершения; проверьте установку и наличие `configs/tsv` рядом с языковыми моделями в каталоге tessdata, выбранном через `TESSDATA_PREFIX` или системной установкой.

Любой результат OCR требует подтверждения. Уверенность распознанных значений и реквизитов, а также общих значений, которые могли попасть из OCR в строки, ограничена 0,49 — ниже минимального настраиваемого порога сравнения 0,50. Нераспознанные номера позиций и артикулы тоже остаются неподтверждёнными: их отсутствие не считается доказанным. Снижение порога не подтверждает OCR автоматически. При низкой средней уверенности OCR числовая ячейка остаётся пустой. Оценки управляют направлением на проверку и не являются измеренной вероятностью правильного распознавания.

Откройте исходный файл и сверьте каждую страницу с распознанным результатом: реквизиты и даты, номера позиций и артикулы **посимвольно** (например, `1` и `l`), наименования, единицы, количества, цены, суммы, валюту и НДС. Проверьте также пропущенные столбцы, строки и страницы. Для строк таблицы имя файла и номер страницы в `field_sources` помогают найти место в оригинале; номер строки и `excerpt` относятся к распознанному тексту, а не являются изображением оригинала. Для общих реквизитов страница может быть неизвестна — тогда проверьте весь файл. Исправления и подтверждения выполняет человек; OCR не угадывает правильный символ.

Таблицы PDF без повторной шапки на следующей странице восстанавливаются только при совпадении расположения столбцов; такие строки сохраняют ссылку на страницу и требуют проверки специалистом. Неоднозначные таблицы помечаются неполными. На смешанной странице текстовая таблица и OCR-таблица автоматически не объединяются, чтобы не удвоить позиции: требуется сверка с оригиналом. Изображения, недоступный Poppler или нераспознанные строки не позволяют автоматически считать документ полным.

## Пример текстового формата

```text
Накладная № N-001 от 20.10.2026
Контракт № GK-2026-001
Дата: 20.10.2026
Валюта: RUB
Цены включают НДС: да
Ставка НДС: 20

Позиция;Артикул;Наименование;Ед. изм.;Количество;Цена;Сумма
1;BENCH-01;Скамья парковая;шт.;8;1 200,00;9 600,00
```

Допустимы разделители `;`, табуляция, `|` и стандартный CSV с запятой. Числа с десятичной запятой в CSV с разделителем-запятой нужно заключать в кавычки. Пробелы, неразрывные пробелы и десятичная запятая нормализуются. Даты принимаются в форматах `ДД.ММ.ГГГГ`, `ДД/ММ/ГГГГ` и `YYYY-MM-DD`. Буквы в числах не заменяются догадками: `1O` остаётся неизвестным значением, а исходный фрагмент сохраняется.

Товар связывается через отдельную колонку `Позиция` или `Артикул`. Номер строки таблицы сам по себе не считается номером позиции контракта. Пустая валюта и неизвестный налоговый базис не заменяются RUB или НДС по умолчанию. Если таблица содержит две колонки одного поля, например две цены, выбор остаётся за пользователем.

Для дополнительного соглашения поддерживаются реквизиты `Действует с`, `Срок поставки`, `Подтверждено`, `replacement_spec_id`, `base_document_id`. Признак подтверждения передаёт решение специалиста о применении документа; парсер не проверяет юридическую действительность изменения.

## Программный вызов

```python
from pathlib import Path
from kontrol.extract import extract_document, ExtractionError

result = extract_document(Path("examples/delivery_8.csv"))
print(result.document.model_dump_json(indent=2))
print(result.needs_review, result.warnings)
```

Для неизвестного шаблона можно передать `document_type="delivery"`, `contract_id="GK-2026-001"` и `metadata={"number": "N-001", "date": "2026-10-20"}`. Значения из `metadata` отмечаются как заданные пользователем. Поля `items`, `id`, хеш и ссылки на источник этим параметром изменить нельзя. Для английского скана передайте `metadata={"ocr_language": "eng"}`. Подтверждённые пользователем изменения сохраняются через механизм исправления документа, а не через повторное изображение распознавания.

При работе через API загруженный оригинал доступен по `GET /api/cases/{case_id}/documents/{document_id}/file`. После сверки сохраните исправленный `document` через `PUT /api/cases/{case_id}/documents/{document_id}` с текущим `expected_revision`, `reviewer` и `comment`; в `confirmed_fields` перечислите проверенные реквизиты документа, а в `confirmed_items` — проверенные поля строк по `line_id`. Подтверждайте отсутствие позиции или артикула только после проверки оригинала. Остальные поля останутся неподтверждёнными; не следует повышать их уверенность вручную без проверки.

Невозможность прочитать файл вызывает `ExtractionError`. Файл, который удалось прочитать частично, возвращает `ExtractionResult` с предупреждениями, `needs_review=True` и перечнем пропусков. `is_complete=True` означает, что обязательные поля поддерживаемого шаблона извлечены; этот признак не доказывает наличие всех приложений к реальному контракту. Пропущенную страницу можно выявить по заявленному `expected_pages`, пустой странице или неполноте реквизитов. Без таких данных отсутствие неизвестной страницы автоматически установить нельзя.

## Ограничения ресурсов

Парсер принимает файлы до 25 МиБ; API может устанавливать меньший лимит. PDF ограничен 100 страницами, OCR – 20 страницами за один файл. Распакованное содержимое DOCX не должно превышать 50 МиБ и 3 000 элементов архива. Изображение ограничено 40 млн пикселей. Для Tesseract предусмотрен тайм-аут 45 секунд на страницу, для Poppler – 30 секунд. Многостраничный TIFF следует преобразовать в PDF.

## Проверка извлечения

`python -m unittest discover -s tests -p test_extraction.py -v` проверяет реальные текстовые файлы, табличный PDF, DOCX, числовую нормализацию, источники, неоднозначные поля, отсутствие OCR-языка и фактический английский OCR при наличии Tesseract. Отдельные регрессионные проверки моделируют некорректный вывод Tesseract при отсутствии `configs/tsv`, пустой корректный TSV и ошибку в артикуле при высокой оценке OCR, включая минимальный порог сравнения. Для генерации PDF в тестах нужен `reportlab`. PDF и DOCX создаются внутри временного каталога и читаются тем же публичным API. Эти проверки подтверждают поведение на конкретных синтетических образцах; они не измеряют качество распознавания реальных закупочных документов.

Документация используемых средств: [pdfplumber](https://github.com/jsvine/pdfplumber), [командная строка Tesseract](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html).
